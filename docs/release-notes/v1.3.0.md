# 亮点 Highlights

- **编译区可以单独部署**：`tensorplay.compiler.build_aot_package` 把一个 CPU 区域写成
  自带 `model.so`、`weights.bin` 与槽表的目录，调用方用 `load_aot_package` 读回，
  或直接包含生成的 C++ 头文件，运行时不再需要编译器。GPU 区域以
  `build_gpu_package` 打包：共享对象、常量与 `kernels/` 下的设备内核二进制一起交付，
  入口点按录制到的网格、线程数与参数重新加载并启动它们。两者都拒绝无法如实描述的
  调度（非 C++ 调度、未降级到设备内核的 GPU 区域、设备上的输入混入 CPU 包）。
- **动态形状与图重放落地**：`tp.compile(dynamic_shapes=...)` 接受逐参数的
  `Dim`/`None`/整数规格，命名轴变为符号、未命名轴保留示例尺寸并在复用前守卫；
  `config.automatic_dynamic_shapes` 默认开启，仅在"尺寸变化是唯一差异"时把具体区域
  泛化为动态区域。CUDA graph 改为树式录制：按输入布局分节点、共享同一个内存池、
  以 copy-in/copy-back 对齐地址，推理区域与训练区域都能重放。
- **编译器正确性收口**：联合图重写接入主路径；捕获到的外部值、原地写、多输出区域、
  部分归约梯度、反向读取被提升常量等一批会产生错误数值的问题修复。捕获状态认证
  从每次调用重新遍历改为一次身份比较，单次编译调用的固定开销
  MobileNetV2 0.80 → 0.36 ms、ResNet34 0.72 → 0.25 ms。
- **CPU GEMM 模板**：编译器为静态 M/N/K 的矩阵乘生成 C++ 微内核，按宿主机指令集
  从分块表里选实现，并按形状与缓存决定线程/缓存分块；bias 与可折叠 epilogue 直接
  落进结果的写回循环。支持 f32 / bf16 / f16；权重预打包与运行期才知道行数的形状
  被明确拒绝，交给其他路径。
- **Meta 设备契约补齐**：激活及其反向、逐元素 clamp、归一化、损失、视图、归约、
  扫描、索引、排序、线性代数、池化、重采样、转置卷积、嵌入/嵌入袋、稀疏、复数、
  填充、随机填充等算子的形状与 dtype 契约都能在 meta 设备上回答，`nn.Module`
  可以直接在 meta 上构建与校验，再迁移到真实设备。
- **损失原语统一接口（不兼容）**：七个此前只回答整平面平均的损失接受 `reduction`，
  与折叠形式共用内核和反向节点；三个 margin 损失把 `margin` 收为普通数值，
  cosine 损失的操作数改名为 `input1`/`input2`。
- **设备与算子接口扩展**：CPU 侧注册 oneDNN 的 `to_mkldnn` / `mkldnn_linear` /
  `mkldnn_convolution` 及反向入口；CUDA 侧补齐逐元素、位运算、比较、激活与特殊函数
  的 `out=` 内核，图捕获支持固定尺寸的 `unique`/`topk` 复用输出缓冲；新增
  `matmul.allow_fp16_accumulation`、`Stream.priority_range`、`Tensor.nbytes`、
  float8 原生序列化与标准库 zstd 检查点流。
- **Windows 发布链路恢复**：内核增长再次触碰 `lib.exe` 的 4 GiB 归档上限，
  本轮把 CUDA 后端改成目标库并直接链进扩展模块（不再经过归档）、配合全程序优化
  （`/GL` + `/LTCG`）、MSVC 侧省略显式 ISA 分级副本、以及与 MKL 共用一套
  OpenMP 运行时收口；Windows 轮子重新可发布。

# 不兼容变更 Backwards Incompatible Changes

### 损失原语接受 `reduction`，margin 收为数值

`l1_loss`、`kl_div`、`soft_margin_loss`、`poisson_nll_loss`、`margin_ranking_loss`、
`hinge_embedding_loss`、`cosine_embedding_loss` 的底层入口此前只回答整平面平均，
调用方无法表达逐元素或求和形式。现在它们接受整数 `reduction`（0 逐元素、
1 平均、2 求和，默认 1，与既有原语一致），并复用折叠形式的内核与反向节点；
只回答平均的原生实现已删除。`kl_div` 同时接受 `log_target`。

三个 margin 损失的 `margin` 从"标量或张量"收为普通数值，cosine 损失的操作数
改名 `input1`/`input2`。

```python
# 之前：只有平均，margin 可以是张量
loss = tp.l1_loss(x, y)
loss = tp.cosine_embedding_loss(a, b, target, margin=tp.tensor(0.5))

# 之后：reduction 可显式选择，margin 传数值
loss = tp.l1_loss(x, y, reduction=2)          # 求和
loss = tp.cosine_embedding_loss(
    input1=a, input2=b, target=target, margin=0.5,
)
```

### 编译器不再接受未生效的开关

`tp.compile(isolate_recompiles=...)` 此前被接收后原样丢弃，两种取值结果相同。
隔离本来就按编译单元生效，不再提供这个开关；现在传入会直接得到 `TypeError`。

`tp.export(strict=True)` 此前与 `strict=False` 被当作同一个捕获。本构建只实现
"录制一次执行"的捕获，因此 `strict=True` 现在抛出 `GraphCaptureError` 并说明原因，
`strict` 也必须是布尔值。

### Python 3.10 退出发布矩阵

预编译轮子覆盖 Python 3.11–3.13；`requires-python` 下界为 3.11。3.14 与 3.15
仍可从源码构建，但没有预编译轮子，也不再声明 3.10。

# 弃用 Deprecations

以下名字保留到 2.0.0，使用时会发出 `DeprecationWarning`：

- `tensorplay.metrics.functional.specicity_at_sensitivity`（拼写错误的旧名）
  → `specificity_at_sensitivity`。
- `Metric._update_called` → `Metric.updated_called`。

# 新特性 New Features

### 编译器（stax）

- **部署包**：CPU 包提供 `build_aot_package` / `load_aot_package`，入口签名为
  `aoti_entry(inputs, outputs, sizevars)`，常量经 `aoti_set_constants` 一次交付；
  槽表同时写成 `metadata.json` 与 `aoti_metadata.h`。包内符号按自身绑定，同一进程
  加载两个包不会共享槽表。GPU 包由 stax 后端提供 `build_gpu_package` /
  `load_gpu_package`，内核二进制放在 `kernels/` 下，入口按录制结果重新启动。
- **动态形状**：逐参数 `Dim`/`None`/整数规格、`mark_static` 钉住轴、图内标记以守卫
  固定尺寸；自动动态特化只在尺寸是唯一差异时生效，数据相关分支、自动微分、模块
  状态、dtype、device 与布局差异仍走普通特化。`export` 暴露
  `check_dynamic_shapes` 做同样的校验。
- **图执行**：按输入布局树式录制 CUDA graph（共享一个内存池），训练区域也能通过
  录制图重放；捕获标记可通过公开的 `compile` 生效；`record_function` 的 span 进入
  图并在融合前删除。
- **图重写**：联合图重写（同时读正向与反向）在切分前运行；局部性重排、断言移除、
  `1/sqrt` 改写等 post-grad 重写作用在已定稿的区域上；互逆的 split/cat 对、乘积与
  加数、缩放商等被折叠；推理区域只读的权重在重写前冻结为常量，编译调用签名不变。
- **CPU GEMM 模板**：静态 M/N/K 的 f32/bf16/f16 乘积按指令集选微内核，按形状与
  缓存分块，bias 与可折叠 epilogue 融进写回；不预打包权重。
- **扩展性**：树外设备可以提供自己的代码生成器，不再要求设备实现位于仓库内。
- **降级覆盖**：新增卷积（1D/3D）、任意秩转置卷积、1D/3D 池化与自适应池化、
  group norm、带掩码的 attention（掩码作为操作数传递）、双线性/最近邻/最大池化
  反向、直方图、中位数、矩阵范数、内积与距离、嵌入袋、指数抽样、尾数与指数拆分、
  运行积/极值、批量乘积、多结果调用，以及省略辅助分支的区域重放；常量 cumsum
  直接折叠为等差斜坡。
- **诊断**：调试开关下打印降级回溯；区域名随前端保留并用于诊断与可调用对象；
  `stax.fusion`、`stax.triton`、`stax.max_autotune`、
  `stax.coordinate_descent_tuning` 等此前被吞掉的选项现在真正到达读取方，环境变量
  设置同理。

### Meta 设备

- 覆盖视图与形状构建、归约与扫描、索引与排序、线性代数（含复数与填充）、
  逐元素 clamp、激活及其反向、归一化、损失、阈值/`isclose`/`diff`/`cross`、
  instance norm、卷积与转置卷积（1D/3D）、池化、重采样、嵌入/嵌入袋与稀疏算子。
- 随机填充可在 meta 上记录，模块可直接在 meta 上构建；`copy` 在 meta 上复制值，
  设备迁移被明确拒绝而不是静默通过。
- 元数据实现按域拆分登记，dtype 表与形状/索引/attention/线性代数/损失的契约
  在 meta 上统一校验。

### 前端与序列化

- `Tensor.nbytes` 为只读属性，返回元素字节总数。
- 原生序列化携带 float8 dtype；检查点流优先使用标准库 zstd，旧解释器回退到原编码。
- `div` / `divide` 的 mode 重载暴露到函数面；`relu6`、`selu`、`xlog1py` 提供
  `out=` 重载。

### CUDA

- 图捕获中的固定尺寸 `unique` 与 `topk` 支持 `out=`，复用调用方缓冲。
- `tensorplay.backends.cuda.matmul.allow_fp16_accumulation` 控制 fp16 GEMM 是否以
  fp16 累加；默认改为 float32 累加。
- `tensorplay.cuda.Stream.priority_range` 返回当前设备的优先级区间。
- 补齐逐元素、位运算、比较、激活与特殊函数族的 `out=` 内核。
- Triton 的设备查询与内核启动绑定到本运行时的当前流，不再跨流执行。

### 内核

- CPU 注册 oneDNN 入口：`to_mkldnn`、`to_mkldnn_backward`、`mkldnn_linear`、
  `mkldnn_convolution`（2D/3D）、`mkldnn_linear_backward`、
  `mkldnn_linear_backward_input`、`mkldnn_linear_backward_weights`；2D/3D 卷积
  保留预分配输出的 oneDNN 布局元数据，stax 回退降级把这些入口当作可用候选。
- 损失接口补齐 `reduction`；`triplet_margin_loss` 同时接受 `eps`、`swap` 与
  `reduction`；logits 与 multilabel 系列损失接受 `reduction`。
- `linalg.norm` 在 CPU 上支持 `'fro'` 与 `'nuc'` 拼写。
- `embedding_bag` 的公共重载在 CPU 注册；原地 `ldexp` 在 CUDA 注册；
  `digamma` 支持负反射并注册 `digamma_`。
- `_neg_view` 以延迟元数据携带符号，`_lazy_clone` 通过共享存储字节推迟拷贝。

### 自动微分

- 两个感知 `reduction` 的损失补上梯度；`float_power` 通过 `pow` 的图求导，
  生成胶水也走同一条路径。
- 原地 `dropout` 通过掩码求导；原地 `hardtanh`、原地激活保持梯度；
  `hardswish` 与 `hardsigmoid` 使用原生原地内核。

# 改进 Improvements

### 构建与发布

- **Windows 4 GiB 上限**：CUDA 后端只在目标库里编译一次，对象直接进入扩展模块的
  链接，归档环节不再需要合并出超过 4 GiB 的镜像；p10 同时启用全程序优化
  （`/GL` + `/LTCG`）压缩静态归档，链接时保留 CPU 目标的注册对象；MSVC 侧不再生成
  AVX2/AVX512 的显式 ISA 分级副本（基线仍是 `/arch:AVX2`）；MKL 与 oneDNN /
  原生内核共用 Intel OpenMP 运行时，`omp_*` 查询与并行域看到同一套线程。
- 版本文件每次构建重新生成，不再依赖时间戳；版本生成器按发布标签匹配
  （`v1.3.0` / `v1.3.0-rc1`）。
- macOS 发布轮子固定到 macOS 26，各 macOS lane 迁出已退役的 `macos-14` 镜像。
- 定时 nightly 对每个 main 提交只尝试一次；恢复 trunk 的发布窗口闸门；修正设备
  验收 lane 的名称；关闭自动依赖升级。
- 索引重建以发布页实际包含的轮子为准，不再依赖上游工作流的结论；漏掉的由每小时的
  兜底计划补齐。

### 运行时与工具

- 默认 intra-op 线程数按 cgroup CPU 配额收敛，容器内不再按宿主机核数起线程。
- 卷积算法选型改为每个候选三次采样取中位，除非实测赢家领先 3% 以上否则保留排序头名；
  `TP_CONV_PLAN_DEBUG` 会打印每个形状的排序时间与实际选择。
- 矩阵乘的计划现在同时计时经典接口，窄归约轴上不再被单一库的排序绑死。
- 开启确定性算术后，归约不再选到自由排序的配置。
- 分配失败会报告导致失败的原始错误；二元交叉熵的错误信息指出出错操作数。
- hub 下载加锁、断点续传并校验摘要。

### 基准与验收

- `benchmark/bench_stax_vision.py` 覆盖视觉分类模型的推理、训练与冷编译，输出 JSON，
  并配套 `benchmark/baselines/stax-cpu.json` 基线。
- `benchmark/bench_metax_ops.py` 覆盖逐元素、归约、激活、BLAS、卷积、attention
  六个算子族，支持 `--device cpu` 的主机计时。
- `benchmark/validate_metax_backend.py` 以 CPU float64 为参考，覆盖前向、反向与
  量化回退，逐项打印误差与判定，退出码即结果。

# 问题修复 Bug fixes

### 内核与设备

- 修复 softmax 输出 dtype 被改写、矩阵操作数未校验的问题；softmax 原地路径先读
  尾部块再覆盖。
- 修复归约结果跨 warp 串扰、退化方差归约。
- 修复 layer norm 统计丢失归一化轴、`frobenius_norm` 未按指定轴归约、
  NaN 中位数未返回该 NaN、空均值/空归约不返回 NaN。
- 修复小批量 LU 因子解包越界、分批 solve 共用 pivot 表、子矩阵 `geqrf`/`ormqr`
  输入未拒绝、空 linalg 输入返回未初始化状态。
- 修复只给值的排序在切片边界越界、`index_copy` 源切片越界或几何不匹配未拒绝、
  复数一元算子读取 strided 输入前未打包。
- 修复卷积偏置进入计划与 workspace 无上限、双精度卷积偏置按单精度缩放。
- 修复 `stft` 的 real-pair 形式与频谱多余拷贝、`ctc_loss` 在移动前构造主机长度向量、
  `digamma` 负反射、`nextafter` 未按元素宽度步进。
- 修复 CUDA 上 `floor`/`ceil`/`round` 丢失整型、dropout 布局未保持。
- 修复 3D 池化参数列表未规范化、零步长未拒绝、随机边界未按浮点极值比较；
  修复 1D 自适应池化只接受多元素输出尺寸。

### 前端

- 修复从未对齐的 NumPy 缓冲创建张量时未先对齐、multiprocessing 在无共享描述符时
  无法导入、`cuda`/`mps` 设备参数解析、随机深度掩码未广播到尾部轴。
- 修复动态形状在 `keepdim` 缺 `dim` 时丢轴、空 norm 未返回折叠单位元、
  dtype 重解释接受未定义目标类型。
- 修复自适应最大池化索引选项未转发、GoogLeNet/Inception 权重初始化默认值、
  CTC 未知 reduction 未拒绝。
- 修复 MEGA 回退写入器的 CRC-32 字节序与校验失败的类型。

### 编译器

- 修复捕获外部值后仍复用旧特化、AOT 缓存参数按身份匹配却持有张量、
  示例输入没有参与缓存键。
- 修复多输出区域只把第一个结果算作前向、原地写被 min-cut 丢弃、
  前向无值但有副作用的调用被丢弃。
- 修复反向读取被提升的常量时报 `KeyError`、部分归约梯度按输入整形状回铺、
  反向扫描按值聚合而漏掉同一值的多次使用。
- 修复视图的框在值未写入时不可读、外部调用在检查 stride 前未物化、
  常量折叠不是图遍历、动态维度边界与关系未在每次调用校验。
- 修复设备变更的转换降级、scatter 写入的别名与重叠检查、`layout_checked`
  在重放中被忽略、多输出与原地写相关的若干重放错误。

### 构建与 CI

- 修复 ROCm 兼容层缺少扩展批归一化入口、非 const 批归一化指针与旧版卷积算法默认值。
- 修复 ROCm 7.2 的 warp 同步内建要求 64 位掩码：相关内核改用 64 位掩码，32 行折叠
  显式带上行宽，`dirichlet` 行归一化按块宽而不是硬件波宽跨步。
- 修复 AMD 侧翻译产物无法编译的若干写法：主机/设备双端 lambda 里的 `std::min`、
  初始化列表形式的 `std::max`、绕过归约包装头直接引用的块扫描头文件、
  只在设备端构造的激活函子，以及另一套求解器没有的批处理特征分解入口。
- 修复 macOS 退役镜像、设备验收 lane 名称、nightly 重复尝试同一提交。
- 修复生成的 kernel 签名未以全局命名空间为根，避免被外层命名空间捕获。
- 修复 FFT 与若干 AVX2 快路径未加 x86 工具链守卫导致的其他架构编译失败。

# 性能 Performance

### 编译器运行时

视觉模型基准为 CUDA（RTX 3090），16 批、224 输入，取 10 次中位数。

- 捕获状态认证改为一次身份比较：MobileNetV2 单次编译调用的固定开销
  0.80 → 0.36 ms，ResNet34 0.72 → 0.25 ms。
- bias 移出乘积 epilogue 后，卷积计划不再被分块归约内核误导：
  ConvNeXt-tiny 推理 7.49 → 6.76 ms。
- 卷积算法每个候选采样三次取中位，同一模型跨进程的波动从 9.2–13.5 ms
  收敛到 9.4–9.5 ms（resnet18 训练）。
- 乘积计划同时比较经典接口的排序：窄归约轴 25088×96×384 上由 171 µs 降到 106 µs。
- 稳态调用路径上，模块属性读取在无写入时跳过、常量描述按调用去重、AOT 包装表
  每个模块只建一次、记录图按布局重放；推理区域可直接复用已完成的区域。

### CPU 与注意力

- **窄头注意力路由**（#51）：`heads <= 4` 且 `head_dim <= 64` 时，阻塞式融合内核的
  可调度 tile 数不足以喂满线程池，改为物化后走组合路径；更宽的头布局保持融合内核。
  ViT-tiny/16 在 384×384 输入下的完整 attention block 从 **1.27x 慢** 变为 **1.06x**；
  绑 8 个 P 核、8 线程实测，波动 <1%。
- **路由阈值按头数与长度扩展**：五到七头、`head_dim <= 64`、不超过 768 token
  同样走组合路径（实测快 1.2–1.7x）；八头、`head_dim=128` 或更长的序列留在
  融合内核（组合路径慢 5–35%）。f64 在五头以上排除，组合路径多一倍访存。
- 归约：整张量归约不再走元素迭代器；全归约用瘦身单块内核，短行用单 warp，
  短 arg 归约用 warp 树；keepdim 归约省掉多余的 strided 视图；var/std 全归约
  改两遍法；max/product 归约有 AVX2 分级实现。
- 池化与索引：窗口沿线铺开、按 plane/row band 切分自适应池化网格、把窗口索引
  降到最小位宽、`nonzero` 按并行度切 tile 并单遍填充。
- 归一化按整向量结束一行、成块取对数、寄存器内 lane 折叠；`softmax` 与融合
  归一化减少重复访存。
- FFT：CPU 谱变换改走 MKL 计划，2D 复数 FFT 在线程池内按行列并行。
- 逐元素：比较、`fmod`、取整除法、clamp、PReLU、ELU/logit/hardswish/hardsigmoid
  梯度等补齐 AVX2 lane sweep；`cumsum`/`cumprod` 整数链每次前进一对，int64
  行 33 元素快 1.45x；`hypot` 保持单精度；`gelu.out` 直接写目标缓冲。

### CUDA 内核

- 64×64 全归约微基准：`nanmean` 26.6 → 20.86 µs，`var_mean` 13.18 → 9.35 µs，
  `std_mean` 15.4 → 13.23 µs，`_standard_gamma` 8.86 → 7.08 µs，
  `linalg.powsum` 10.56 → 8.39 µs。
- 深度卷积在 plane 边缘整窗读取一次，ConvNeXt stage-4 几何上 7×7 卷积
  69.6 → 16.5 µs，输出逐位一致。
- 分解与求解：`cholesky_solve` 用单次 `potrs` 合并两次三角求解，与参考实现的
  耗时比 1.07x → 0.97x；`ormqr` 直接交出求解器的列主序平面，1.14x → 0.98x。
- `nonzero` 坐标在能放下时用 32 位拆分、扁平坐标免除法；`one_hot` 单遍 int64、
  `bincount` 的 minmax 扫描向量化、radix-select 的位数收窄到两位。
- 短归约按 CTA 切分、按轴决定每线程下限；归一化行整向量化、Dirichlet 归一化
  拆成求和与除法两遍；KL、NLL、multi-margin 等损失融合为单遍。
- 统计与采样：`histogram` 单遍计数，`gamma` 采样降低块大小提升占用率，
  短全局 arg 归约单块完成；逆 Hermitian FFT 改用完整实数变换。

### 前端与数据管线

- DataLoader 批数据经由复用的共享段传递；接收侧不再每批重建段，1.5 MB 批的
  页错误开销约 1.5 ms、38 MB 批约 31 ms。
- 多进程张量传输对小张量走内联（上限 512 KiB，实测 2–4x 快），大张量才建共享段；
  描述符共享复用持久连接。
- 派发：操作包调用缓存上一次入口、张量参数按张量形参解析、包装缓存属性名内联、
  记录型路径保持 GIL；设备放置结果进入身份缓存。
- 恒等视图在不需要梯度时返回操作数或元数据副本；`dropout` 非训练时直接返回输入；
  `pixel_shuffle` 走原生内核；`max_pool1d` 走原生内核。

### MetaX C500

实测环境：MACA 3.3.0，fp32，50 次均值。完整数据见下表；可复现脚本为
`benchmark/bench_metax_ops.py` 与 `benchmark/validate_metax_backend.py`。

| 族 | 用例 | ms | 派生速率 |
| --- | --- | ---: | ---: |
| 逐元素 | add / mul 16M | 0.144 / 0.143 | 1395 / 1405 GB/s |
| 逐元素 | exp / log 16M | 0.102 / 0.103 | 1313 / 1304 GB/s |
| 逐元素 | relu 16M（`out=`） | 0.270 | 498 GB/s |
| 归约 | sum / max 16M | 0.074 / 0.076 | 905 / 878 GB/s |
| 归约 | softmax 4096² | 0.113 | 1185 GB/s |
| 激活 | sigmoid / tanh / gelu / silu 16M | 0.102–0.105 | 1284–1315 GB/s |
| BLAS | mm f32 4096 | 4.691 | 29.30 TFLOP/s |
| BLAS | mm f16 4096 | 0.691 | 199.03 TFLOP/s |
| BLAS | bmm f32 8×1024×1024 | 0.720 | 23.85 TFLOP/s |
| 卷积 | conv2d 8×64×56×56 k3 | 0.122 | 15.21 TFLOP/s |
| attention | sdpa 2×8×1024×64 | 0.786 | 5.46 TFLOP/s |

逐元素与激活族都停在约 1.3 TB/s，已到该卡访存上限。`relu` 带 `out=` 只有
498 GB/s 是 `out=` 路径的缺口：`relu` 的 `out=` 走"算到临时张量再整块拷贝"的
复合路径，多付一次 64 MB 读 + 64 MB 写；不带 `out=` 时是 0.103 ms，原地版
0.098 ms。

**数值一致性**（设备 vs CPU float64，按参考幅度归一）：fp32 全部 3.0–5.0e-08
（半个 ulp），fp16 4.1e-04、bf16 4.1e-03（各自半个 ulp），int32 精确，
conv2d/conv3d 5.0e-08/3.0e-08，融合 attention 与组合数学路径 4.2e-08。

**反向**：逐元素 3.9e-08、conv2d 中心差分 1.2e-03（受差分步长限制）、
sdpa 4.0e-08。**量化回退**：int8 往返与 `quantized_matmul` 都落在半个量化步长，
设备输入走主机回退后语义不变。

**体积**：1.3.0 周期的 MetaX 构建中 `libp10.so` 为 2.24 GB，设备镜像
`.mc_fatbin` 占 93.7%；`-O2` 与 `-O3` 的产物只差 80 字节，压缩与降优化级别
都不是杠杆，真实杠杆是削减 dtype × 算子的实例矩阵。

# 安装 Installation

发布矩阵：CPU 轮子覆盖 linux x86_64 / linux aarch64 / macOS arm64 / windows x86_64，
CUDA 轮子本轮只出 cu130（linux x86_64 与 windows x86_64），ROCm 轮子为
rocm72-multiarch，Python 3.11–3.13；macOS arm64 轮子默认带 MPS 后端。
MetaX（MACA）走手动发布通道（`+maca330`），不进入自动矩阵。

```bash
# CPU 轮子（PyPI；macOS 轮子内置 MPS 后端）
pip install tensorplay==1.3.0

# CUDA 13.0 轮子
pip install tensorplay==1.3.0 \
  --index-url https://download.tensorplay.cn/whl/cu130/ \
  --extra-index-url https://pypi.org/simple

# ROCm 轮子（AMD / HIP，rocm72-multiarch）
pip install tensorplay==1.3.0 \
  --index-url https://download.tensorplay.cn/whl/rocm72-multiarch/ \
  --extra-index-url https://pypi.org/simple
```

MetaX 轮子走手动发布通道，由 C500 构建后附在发布页，需要自备 MACA SDK
（3.3.0 验证）与 C500 驱动：

```bash
pip install tensorplay-1.3.0+maca330-cp312-cp312-linux_x86_64.whl
```

该轮子在 CPython 3.12 上验证；其余版本需在 C500 上重新构建。
